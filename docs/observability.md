# Observability

| Signal | Implementation | Destination |
|---|---|---|
| **Traces** | OpenTelemetry (`otelgrpc` handlers; every Postgres query, batch and connect is a CLIENT span below the request span through `otelpgx`, named by the SQL operation such as `SELECT`, with the statement text but never the parameters; no span without a recording parent, so start-up migrations and background sweeps are not traced), OTLP/gRPC exporter (batch processor, queue bounded at 2048), W3C TraceContext + Baggage propagated to every downstream call. Sampler from `OTEL_TRACES_SAMPLER` (SDK default `parentbased_always_on`) | Alloy `:4317` -> Tempo |
| **Metrics** | Prometheus default registry: `grpc_server_*` (go-grpc-prometheus with handling-time histogram), Go runtime and process metrics. Served as Prometheus text on `:9090/metrics` (`METRICS_PORT`) and, because the same registry is bridged into OpenTelemetry, also pushed over OTLP every 15 s (metric names identical). Plus `build_info{service,version,commit} 1` and the database pool: `db_pool_connections{state=acquired|idle|constructing}`, `db_pool_connections_max`, `db_pool_acquires_total`, `db_pool_empty_acquires_total` (acquisitions that had to wait), `db_pool_canceled_acquires_total`, `db_pool_acquire_seconds_total`, `db_pool_new_connections_total`, `db_pool_destroyed_connections_total{reason}` | Alloy scrapes `:9090` -> Mimir |
| **Logs** | `logrus`, one JSON object per line on stdout, plus an OTLP/gRPC hook (`otellogrus`) | stdout -> Alloy -> Loki; OTLP -> Alloy -> Loki |
| **Profiles** | Pyroscope Go SDK (CPU, alloc/in-use objects and space, goroutines, mutex, block), only with `PYROSCOPE_ADDR`; tags `service_name`, `version`, `environment` | Pyroscope |

**Telemetry contract** (the code is `internal/obs`, the same package in every Go service): telemetry is on only if `OTEL_EXPORTER_OTLP_ENDPOINT` is a valid absolute http(s) URL; `OTEL_SDK_DISABLED=true` forces everything off (profiling too); profiling only with `PYROSCOPE_ADDR`. Start never waits for the collector (the exporters connect in the background) and on SIGTERM the flush is cut off after 4 s, so a blackholed collector cannot hold the process (unit-tested with a listener that never answers: start and shutdown both return within the bound).

**Resource attributes** on every signal: `service.name` (`OTEL_SERVICE_NAME`, default `user-service`), `service.version` (`SERVICE_VERSION`, else build info, else `dev`), `service.namespace=everly`, `deployment.environment` (`DEPLOYMENT_ENVIRONMENT`, default `local`), `service.instance.id` (hostname). `OTEL_RESOURCE_ATTRIBUTES` is applied last.

**Log shape** (one shape for all services): `timestamp` (RFC 3339, UTC, milliseconds), `severity` (`debug`, `info`, `warning`, `error`), `message`, `service`, `version`, `trace_id` and `span_id` (hex, only while a valid span is active, never empty or all zeros), `request_id` (when the caller sent one), `error` (string, on errors), plus the call's own fields (for example `order_id`). Level from `LOG_LEVEL`. `trace_id`/`span_id` come from the context of the log call: handlers and clients log with `log.WithContext(ctx)`, the formatter reads the span from it. Calls without a context (startup, background work) have no ids. No card data, tokens or e-mail addresses are logged.

**Startup and version**: the first line is `message: "starting"` with `version`, `commit` and `environment`; `version`/`commit` come from `SERVICE_VERSION`, ldflags `-X <module>/internal/obs.Version=` / `.Commit=`, or the VCS data Go embeds (the Dockerfile links `SERVICE_VERSION`, `SERVICE_COMMIT` and `BUILD_TIME` build arguments into `Version`, `Commit` and `BuildTime`; the pipeline passes all three; a plain `docker build` without them reports `version: "dev"`, `commit: "unknown"` and no `build_time`). `build_time` is logged on the `starting` line when set; `build_info` keeps its labels `service`, `version`, `commit`. Panics are logged as one JSON line (`message: "panic"`, `error`) before the process dies; a startup error is one JSON error line, exit 1.

**pprof** is off. `PPROF_ADDR=127.0.0.1:6060` starts a separate listener; it is never on the metrics port.

**Graceful shutdown** (SIGTERM or SIGINT): health goes `NOT_SERVING`, `GracefulStop` with a 5 s cap (then `Stop`), then the telemetry flush runs, cut off after 4 s, the pool is closed: the process exits within 9 s even when the collector is blackholed. Run against a listener that never answers (OTLP and Pyroscope both pointed at it, database unreachable) the binary exited 0 about 4 s after SIGTERM (smoke run, not part of the unit tests; with a reachable database not re-measured).

**Business counters (OBS-20):** none, on purpose. The standard names orders placed, stock reservations and payments by outcome; the user service owns none of them, and the gRPC RED series (`grpc_server_handled_total{grpc_method,grpc_code}`) already show the outcomes by status: `Login` `UNAUTHENTICATED` (wrong credentials) and `RESOURCE_EXHAUSTED` (limiter), `Register` `ALREADY_EXISTS` and `RESOURCE_EXHAUSTED`. Decision of 2026-11-22: no extra counter (a per-reason counter would be a new feature, the service is frozen after this change set). Logs contain user ids (`user_id` field), never e-mail addresses, passwords, tokens or hashes (a unit test and an integration test fail if a log line contains any of them; the new log-shape test checks the e-mail address, the password and the token again). Background work (the expired-session clean-up) has no request, so its lines carry no trace ids.

Example query (not run against a live backend): `sum by (grpc_method, grpc_code) (rate(grpc_server_handled_total{grpc_service="hipstershop.users.UserService"}[5m]))`.

## Switches

Telemetry is off unless `OTEL_EXPORTER_OTLP_ENDPOINT` is a valid absolute http(s) URL; `OTEL_SDK_DISABLED=true` forces it off; profiling needs `PYROSCOPE_ADDR`. The legacy `COLLECTOR_SERVICE_ADDR` and `ENABLE_TRACING` are no longer read. Details: [configuration](configuration.md).
